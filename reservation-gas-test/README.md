# 大人の自由研究所：所有者限定の予約接続テスト

このフォルダはGoogle Apps Scriptへ手動で貼り付けるテスト用です。
既存サイト・booking.htmlは変更していません。一般のお客様には使えません。

## 入れるファイルは2つ

- `Code.gs`：Googleカレンダーの空き状況取得・50分の仮予約・運営への通知
- `Booking.html`：これまでの予約ページのデザインを維持した接続用HTML

`booking-client.js`は検証用の控えです。すでにBooking.html内に含まれるため、Apps Scriptへの追加は不要です。

## 作業手順

1. 今のApps Scriptのコードをコピーし、バックアップを残します。既存のテスト予定も削除されません。
2. プロジェクト内の既存のコードを`Code.gs`の内容に置き換えます。他のファイルに同じ名前の関数・定数が残らないようにします。
3. 左の「ファイル」横の「＋」→「HTML」を選び、名前を `Booking` にします。
4. できたHTMLの中身を消し、`Booking.html`の内容を貼り付けます。
5. 保存し、上部の関数選択で `checkSetup` を選んで「実行」。これは接続先の確認のみで、予定作成・メール送信はしません。カレンダーの読み書きとメール送信の権限を求められたら、自分が作ったこのプロジェクトであることと権限内容を確認してください。
6. 実行ログのカレンダー名が予定を入れたカレンダーと同じか確認します。別のカレンダーを使う場合は、Code.gs先頭の `calendarId` にそのIDを設定します。一般公開する必要はありません。
7. 「デプロイ」→「デプロイをテスト」→種類「ウェブアプリ」でテストURLを開きます。画面にこの選択がない場合は、既存デプロイを「新しいバージョン」に更新します。その際も「実行するユーザー：自分」「アクセスできるユーザー：自分のみ」を維持してください。一般公開にはしません。
8. Google側のテストURLを、作成したGoogleアカウントでSafari等の通常ブラウザから開きます。ダウンロードしたHTMLをファイルプレビューで開くだけでは接続できません。

## テストすること

- 予定を入れた日を選ぶと、その予定と重なる50分枠が薄くなり、選べないこと。
- 「予定あり」の終日予定は全枠をブロック。「空き時間」の予定はブロックしません。
- 予約枠は10:00〜20:00開始、各50分、毎日受付、日本時間です。テスト用の受付期間は本日〜90日先です。
- 空いている時間で名前・メール・相談方法を入力し、同意→内容確認→「仮予約を申し込む」。この操作は実際にカレンダーへ【仮予約・テスト】を作り、adultcuriositylab@gmail.comへメールを送ります。お客様宛ての自動返信はありません。
- 2つのタブで同じ時間を選び、先に片方を送信した後にもう片方を送信すると、後者は重複エラーになること。
- 同じ申し込みを連打・再確認しても予定と通知メールが増えないこと。
- 登録成功・メール失敗は分けて表示されます。通知メール失敗でもカレンダー登録は取り消しません。
- 送信後に通信が切れた場合は、画面を閉じず、同じ申し込みの結果を再確認します。端末の画面を閉じてしまうと、このテスト版では送信中の受付番号を復元できません。カレンダーを確認してから再操作してください。
- テスト終了後、不要な【仮予約・テスト】予定は自分で削除してください。削除は自動では行いません。

## 公開前に別途行うこと（今は未実装）

所有者以外を拒否するサーバー側の制限を入れています。公開設定だけ「全員」にしても利用できません。
一般公開前に、迷惑送信対策、アクセス頻度制限、必要に応じたメール確認、受付期間・締切、仮予約の保留期限・取消方法を決めて実装します。
個人情報はカレンダーと運営へのメールに保存されます。カレンダーの共有先・公開設定・個人情報の保存期間を確認してください。
同時送信のロックはこのスクリプト経由の予約に有効です。カレンダー画面から同時に手入力した予定まで、同一トランザクションにするものではありません。
受付番号の再送記録はScript Propertiesに最長約100日保存します（氏名・メール・相談内容は保存せず、内容のハッシュと受付状態のみ）。
Google側には実行時間、メール送信数、保存容量等の上限があります。永続的な無料・無制限や通知メールの到達は保証されません。
トップページ・プライバシーポリシーへのリンクは既存のNetlifyサイトへ向けています。公開先を変える場合はCode.gsのsiteUrlを変更してください。

## 検証状況

JavaScriptの構文確認と、Googleサービスを模したテストで重複・再送・日時検証・通知失敗等を確認しています。
実際のGoogleアカウントでの認証、カレンダー登録、メール到達、Safariでの表示は、上記の所有者限定テストで確認が必要です。
